# NEKalkan — техническое описание

## 1. Устройство

```
1С:Предприятие (Native API)
   │  tVariant, IMemoryManager, AddError
   ▼
native1c.cpp      — мост к платформе: IComponentBase, преобразование tVariant ⇄ байты, память платформы, экспорты DLL
   ▼
api1c_dispatch.cpp / api1c.cpp — 60 методов, 193 константы, коды ошибок, текст последней ошибки
   ▼
kalkan.cpp        — класс Kalkan: поведение функций KalkanCrypt SDK (ключ, сертификаты, подпись, проверка, ошибки)
   ▼
cms.cpp  xmldsig.cpp  p12.cpp  x509.cpp  crl.cpp  certprop.cpp     — форматы и протоколы
asn1.cpp xml.cpp (+C14N) codec.cpp                                  — ASN.1/DER/BER, XML-парсер и канонизация, Base64/PEM/UTF
gost3410.cpp rsa.cpp ciphers.cpp hash.cpp legacy.cpp bignum.cpp     — примитивы
rt.cpp plat_win.cpp                                                 — среда выполнения (память, memcpy, файлы, время, ГСЧ)
```

* Диспетчер не знает про Native API: параметры и результаты идут через интерфейс `ApiHost`. Поэтому один и тот же код
  проверяется автотестами (тестовый хост в `capi.cpp` поверх массива значений) и работает в 1С (`native1c.cpp` — хост поверх `tVariant`).
* Сборка даёт **две** DLL из общего кода: `NEKalkan.dll` (боевая, 5 экспортов Native API, импорт только KERNEL32/ADVAPI32) и
  `NEKalkan_test.dll` (то же ядро + тестовый интерфейс `nek_*` для `tests/`). Тестовые функции в боевую DLL не попадают.
  Ключ `-Guard` добавляет третью сборку с «охранными страницами» памяти: каждый блок живёт на отдельных страницах, выход за границу и
  обращение после освобождения немедленно дают исключение, а счётчик живых блоков позволяет искать утечки.
* Среда выполнения — **C++17 без стандартной библиотеки** (clang, `-ffreestanding -nostdlib`): без CRT, исключений и RTTI.
  Собственные `Bytes` (буфер с завершающим NUL и затиранием при освобождении), `Vec<T>`, `Span`, `memcpy/memset/…`,
  `__chkstk`, `operator new/delete` на `HeapAlloc`. Любой отказ выделения памяти возвращается как `false`/код ошибки.
* Состояние хранится только в объекте `ApiState` (внутри объекта компоненты): ключ, доверенные сертификаты, журнал, последняя ошибка.
  Глобальные данные — только неизменяемые таблицы и кривые ГОСТ, строящиеся лениво потокобезопасно (атомарная инициализация).
  Один объект компоненты — один поток.

## 2. Соглашения НУЦ РК

| Что | Как |
|---|---|
| Открытый ключ ГОСТ в сертификате | `X ‖ Y`, каждая координата — little-endian, внутри OCTET STRING |
| Подпись ГОСТ | `r ‖ s`, каждая половина — little-endian |
| Дайджест → число `e` | little-endian чтение вывода Стрибога |
| Закрытый ключ в PKCS#12 | число big-endian; порядок байт определяется сверкой `Q = d·P` с открытым ключом сертификата |
| OID ГОСТ 2015 | `1.2.398.3.10.1.1.2.*` (подпись 256/512), хэш — `…1.2.2.*`; ГОСТ 2001 — `1.2.398.3.10.1.1.1.*` |
| Стрибог | ГОСТ Р 34.11-2012, 256 и 512 бит |
| ГОСТ 34.11-94 (вариант НУЦ РК) | обратный порядок байт вывода; пустой ввод обрабатывается тремя шагами, как у Калкана |
| Кривые | TC26 256-A, 512-A, КриптоПро A/B/C (для ГОСТ 2001) |

Проверка подписи ГОСТ дополнительно проверяет принадлежность точки кривой и подгруппе (`q·Q = ∞`), диапазоны `r, s`.

## 3. Форматы

**PKCS#12.** BER с неопределённой длиной приводится к DER; KDF по RFC 7292, шифры PBE 3DES, RC2-40/128, PBES2 (PBKDF2 + AES/3DES).
MAC обязателен (неверный пароль → `KCR_INVALIDPASSWORD`). Ключи, алгоритм которых не ГОСТ 34.10-2015 и не RSA (в том числе ГОСТ 2001
и старые схемы НУЦ), распознаются и дают `KCR_UNKNOWN_ALG`.

**CMS.** `SignedData`, CAdES-BES: атрибуты `contentType`, `messageDigest`, `signingTime`, `signingCertificateV2`; attached/detached;
несколько `SignerInfo`; «подпись готового хэша». Проверка привязывает подписанта к сертификату по
`issuerAndSerialNumber` либо `subjectKeyIdentifier`, проверяет хэш сертификата в `signingCertificateV2`, цепочку до загруженного корня,
срок действия, признак УЦ (`basicConstraints`), `pathLen` и `keyCertSign` у издателей.

**XMLDSig.** Собственный XML-парсер с пространствами имён; канонизация C14N 1.0/1.1 и Exclusive с комментариями и без
(сверена с libxml2 на 1654 документах). Подпись выполняется в два прохода (вставка заготовки `ds:Signature` → повторный разбор →
канонизация `SignedInfo`), что даёт структуру, совпадающую с Калканом. Несколько подписей: каждая следующая подпись
подписывает документ вместе с предыдущими; при проверке подпись N исключает из ссылки себя и последующие. Узел по `Id` ищется
однозначно (дубликаты `Id` отвергаются — защита от XML Signature Wrapping). Комментарии в same-document-ссылках исключаются (XMLDSig §4.3.3.3).
Пределы разбора: глубина вложенности 256, 4096 атрибутов и 512 объявлений пространств имён на элемент.

**Ошибки.** Коды `KCR_*` — как в SDK. При ошибках проверки возвращаются коды OpenSSL, которые выдаёт Калкан
(`0x8006E07B`, `0x2E09A09E`, `0x0D0680A8`) и тексты вида `error:2E09A09E:CMS routines:…`.

## 4. Мост к платформе 1С

* Порядок виртуальных функций `IComponentBase` совпадает с официальными заголовками 1С .
* Параметры: `unref` раскрывает BYREF (`VTYPE_VARIANT|VTYPE_BYREF`), число параметров обязано совпасть с таблицей (все параметры,
  в том числе необязательные, платформа подставляет через `GetParamDefValue`), строки/BLOB проверяются на длину и NULL.
* Результаты строк/BLOB выделяются через `IMemoryManager::AllocMemory` и передаются платформе; значения `CallAsProc`, которые 1С не заберёт, освобождаются.
  Старые значения BYREF-параметров не освобождаются (их владеет платформа); если одна и та же переменная передана в несколько выходных
  параметров, выделенный в этом же вызове буфер освобождается при перезаписи.
* Кодировки: имена, пароли, XML — всегда UTF-8 для движка; данные — в кодировке обмена (`SetStringEncoding`); невозможное преобразование —
  `WRAP_CONVERSION_ERROR` до выполнения операции. Тексты движка (отчёты, свойства сертификата) — UTF-8 → строка UTF-16.
* Ошибки вызова компоненты (`WRAP_*`) пишутся в журнал регистрации через `AddError(ADDIN_E_FAIL, "NEKalkan", текст, код)`; ошибки криптографии — только кодом.
* Имя класса = имя расширения = `NEKalkan`: платформа 8.3.27 создаёт тип только по имени расширения. `GetClassObject` имя не проверяет.
* `Done()` затирает ключ и сертификаты и забывает менеджер памяти платформы.

## 6. Известные ограничения и планы

* Не реализованы: запрос метки времени TSA и онлайн-проверка отзыва OCSP/CRL по сети (WinHTTP), `SignWSSE`, ZIP-контейнеры `ZipCon*`,
  токены/ID-карты (PKCS#11), чтение системного хранилища Windows, подпись ключами ГОСТ 2001, сборка под Linux.
* Арифметика ГОСТ-кривых не защищена от атак по времени/кэшу (используйте там, где подпись выполняется в доверенной среде).
* `GetCertificatesList` возвращает только сертификат загруженного ключа.
